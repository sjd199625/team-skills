# 页面交付检查

## 开工

- [ ] 已读 `01-frontend-tech-design.md`
- [ ] 已读与当前改动直接相关的来源快照
- [ ] 已读 `iot-frontend-conventions`
- [ ] 已找到同类页面和页面内组件
- [ ] 已确认项目、分支和工作区状态
- [ ] 已把页面/路由/组件映射到真实文件
- [ ] 已列出需要用户确认的阻塞项

## 实现

- [ ] 路由已注册
- [ ] 页面入口存在
- [ ] 组件复用或新建理由清楚
- [ ] API 集中放在项目 API 文件
- [ ] 请求参数和返回解包符合项目
- [ ] 权限、Bridge、登录态没有被绕过
- [ ] 空/加载/错误/重试有落点
- [ ] PC/H5 行为和单位符合项目
- [ ] 没有修改无关文件或做全仓重构

## 页面完成后的手工检查

- [ ] 主流程能打开
- [ ] 主动作能触发
- [ ] 空数据展示明确
- [ ] 接口失败有提示
- [ ] 无权限/未登录行为符合现有页面
- [ ] 刷新/返回/重复操作没有明显异常
- [ ] PC 表格或 H5 列表没有横向溢出

## 验证

- [ ] 已运行项目 lint（如有）
- [ ] 已运行项目 build
- [ ] 已记录实际命令和结果
- [ ] 未运行项明确标注
- [ ] 实现记录已补进 `01-frontend-tech-design.md`

## 常见错误

- 只读技术文档，不看相邻页面。
- 把另一个项目的组件或分页习惯搬过来。
- 在两个不同角色里重复解包。
- 在有 SSR 的模块顶层访问浏览器对象。
- 为了让代码“更通用”改公共组件，但不检查调用方。
- 构建过了就声称页面测试过了。
