# 前端项目画像模板

> 目的：把每次都要重新扫的项目事实集中到这里，减少重复探索。
> 本文件只提交通用模板；真实仓库、环境和个人路径不要提交。

复制为同目录的 `project-profile.local.md`，填写真实内容；该文件已被 `.gitignore` 忽略。

## 角色

| 角色 | 用途 | 本机路径 | package name |
| --- | --- | --- | --- |
| `mobile-h5` | 移动 H5 | `<repo-path>` | `<package-name>` |
| `desktop-admin` | PC 后台 | `<repo-path>` | `<package-name>` |
| `servicer-ssr` | 服务端渲染 H5 | `<repo-path>` | `<package-name>` |

先确认路径存在和 `package.json`；路径变化时更新本地 profile。

## 项目事实模板

每个角色只记录已从代码确认的事实：

- 框架、构建工具、组件库和版本；
- 页面、路由、API、样式目录；
- 请求是否已经解包；
- 权限、Bridge、SSR 和 mock 开关；
- 可复用的同类页面和组件；
- 已知坑和最后一次核对时间。

不要把临时分支、一次性测试数据、真实用户信息或内部地址写进提交文件。

测试执行规则：

- 先确认登录态和真实接口，再写“通过”。
- 登录失败、环境打不开或只有 mock 数据时，写“阻塞”，并记录原因和下一步。
- 不能因为某个入口没登录，就把它从覆盖矩阵里删掉。

## 跨项目约定

- 接口常量放项目 API 文件，不写死在模板或事件里。
- 页面只消费归一化状态，不根据提示文案推导业务结果。
- 先复用同模块页面和公共组件，再考虑新建。
- 构建通过只说明构建通过，不是页面验收。
- 页面能打开不等于真实接口、真实设备或真实登录取通。

## 更新方式

1. 先读当前项目相邻页面和 `package.json`。
2. 只把已经确认的路径、命令、复用点和坑写进本地 profile。
3. 记录核对日期；分支提交变化时重新核对命令和 mock 开关。
4. 本地 profile 不提交，不把真实数据写进公开文档。
