# 精简交付产物契约

默认只产三类文档，不再把需求、设计、开发记录、测试计划和测试报告拆成八份。

```text
docs/<feature>/
├── 01-frontend-tech-design.md
├── 02-test-cases-results.md
├── 03-backend-business.md       # 有后端输入时再生成
├── workflow-state.yaml
└── sources/
    ├── feishu-<doc>.md
    ├── api-<doc>.md
    └── backend-<repo>-<branch>.md
```

## 文件职责

| 文件 | 内容 | 生成时机 |
| --- | --- | --- |
| `01-frontend-tech-design.md` | 需求摘要、范围、页面/路由、组件、状态、接口假设、权限、实现决策、实际改动、已知风险 | 开发前写设计；开发后补实际改动 |
| `02-test-cases-results.md` | 用例编号、前置条件、步骤、预期、实际结果、状态、阻塞原因、构建/lint 和结论 | 页面完成后一次写完并更新结果 |
| `03-backend-business.md` | 接口契约、字段映射、后端调用链、数据来源、状态流转、权限和未确认项 | 有后端分支或接口文档时生成 |

## 合并规则

- 需求不再单独成文；把影响实现的背景、业务规则、不做项和未决问题放进 `01`。
- 测试计划不再单独成文；用例和实际结果放在 `02`，没有执行的用例放“阻塞”，需求不涉及才放“不适用”。
- 实现说明不再单独成文；实际改动、mock/接口差异和风险放进 `01` 的“实现记录”。
- 交付总结不再单独成文；最终结论放在 `02` 末尾，或直接在聊天里汇总。
- 接口联调和后端业务合并进可选的 `03`；没有后端输入时不要生成空文档。

## 来源快照

飞书、接口文档和后端代码都要保留来源：

```markdown
> 来源：<URL 或仓库路径>
> 分支/提交：<branch>@<commit>
> 获取时间：<YYYY-MM-DD HH:mm>
> 读取范围：<章节 / 文件 / 行号>
```

飞书文档保存原始 Markdown 快照到 `sources/`；不要把登录凭据、cookie 或 token 写进文档。

## 文档状态

在 `01` 和可选的 `03` 开头标记：

- `状态：草案`：仍有影响实现的未决问题；
- `状态：已确认`：用户已确认，可作为开发/联调依据；
- `状态：已过期`：需求、接口或分支发生变化。

## 产物优先级

1. 页面/接口/组件设计；
2. 可执行用例；
3. 实际执行结果；
4. 后端事实；
5. 其他背景重复说明。

只有影响开发、测试或联调的结论才需要长期保存。
