## 规则

- 数字来自实际执行，不来自计划。
- 截图和日志路径要能打开。
- 失败用例不要只写“失败”，要写实际看到的结果。
- 没有执行的用例按原因放“阻塞”，必须写原因、责任人和下一步，不要放“通过”。
- 本次需求不涉及的入口写“不适用”，并说明为什么不涉及。
- 核心项目或核心入口没有执行时，结论只能是“部分通过”，不能写“通过”。
- 测试结论不替代代码构建和需求验收。
